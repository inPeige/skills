# 口播稿写作规范

攻略是**查阅型**文本：可以跳读、有表格、有坐标、读者随时能回看。
口播是**线性时间型**文本：听众不能回看，一句没听懂就丢了，念错一个数字就废了。

**这份规范的全部目的，是把前者改造成后者。**

---

## 1. 结构模板（8 段以内）

| 段 | role | 干什么 | 句数 |
|---|---|---|---|
| 开场钩子 | `hook` | 用**具体收益或反常识结论**抓人，禁止"大家好今天讲…" | 1–2 |
| 价值承诺 | `intro` | 说清"看完你能得到什么"＋**来龙去脉**（§8.3），给继续看的理由 | 1–3 |
| 干货主体 | `body` | 攻略核心内容，**按操作顺序**而不是原文顺序重排 | 6–20 |
| 价值兑现 | `like` | 讲完一档硬数据后**立刻**做价值兑现＋点赞引导（§8.1），可 1–3 次 | 1–2 |
| 避坑提示 | `tip` | 最容易翻车的一两条（可选，但强烈建议） | 1–3 |
| 观点收束 | `outro` | "我怎么看"＋"你能拿走什么"（§8.3）。**段数 ≥8 的长稿必带** | 1–3 |
| 行动号召 | `cta` | 让观众做一件事（关注/收藏/评论/下集预告） | 1–2 |

> `like` 与 `outro` 是**独立于 body 的段**，不要塞进 body 段尾——
> 独立成段，分镜才能给它一个专门镜头，句序也仍然整体递增（W217）。

钩子的四种可用写法（选一种，别贪多）。
下面左列是**人读版**（口播文稿.md，带标点），右列是**进 `sentences` 的零标点版**——
抄进 `script.json` 时必须去掉标点，否则吃 W204：

| 人读版（口播文稿.md） | 机器版（script.json sentences） |
|---|---|
| 50级加一套房子，就能开一个每周白拿积分的牧场。 | 50级加一套房子就能开一个每周白拿积分的牧场 |
| 牧场升级最快的不是单人肝，是找人结婚。 | 牧场升级最快的不是单人肝是找人结婚 |
| 养号最烧钱的是修炼果，其实牧场能白换。 | 养号最烧钱的是修炼果其实牧场能白换 |
| 养号党注意，这个系统你八成没开。 | 养号党注意这个系统你八成没开 |

四种钩子分别是：收益前置 / 反常识 / 痛点 / 身份代入。

## 2. 句子规则（机器会检查，见 `check_output.py`）

| 规则 | 原因 |
|---|---|
| **一句一个信息点** | 两句揉一起，画面就没法跟 |
| **≤42 字，理想 12–28 字** | 一口气念得完；也是字幕一行放得下的长度 |
| **`script.json` 的句子零标点** | 配音按文本**逐字锚定**，字幕也是整句直出。`，。？！` 会占位、对不齐。**小数点不算标点**（`17.8` 保留） |
| **数字就是数字：`5000` 就写 `5000`，`2.5` 就写 `2.5`，`第3天` 不写「第三天」** | 把数字转写成汉字是多一次翻译，位数、小数点、单位最容易在这步写错；TTS 能正确读阿拉伯数字，逐字锚定也不要求汉字 |
| **坐标、ID 同样保持数字原样**：`（207,102）` → 机器版 `坐标207102` | 同上；逗号是标点，零标点版里去掉，`tts.txt` 里可以带顿号 |
| **不写括号、书名号、表格符号** | 念不出来。补充信息改成句子 |
| **不写英文缩写**（除非是玩家日常口头就这么说） | `NPC` 可以，`CD` 看受众 |
| **口语连接词**：所以 / 但是 / 而且 / 注意 | 书面语转口语的主要手段 |

> **标点只存在于 `口播文稿.md`（给人读），不进 `script.json`（给机器用）。**
> 两版**文字必须逐字一致**，差别只有标点——否则配音和字幕对不上。
> 用汉字顿号/逗号会把节奏切开，也别写进 sentences。

## 3. 时长与篇幅

默认语速 **5 字/秒**（中文口播常规区间 4.5–5.5）。

- 30 秒 ≈ 150 字 ≈ 10 句
- 60 秒 ≈ 300 字 ≈ 18 句
- 3 分钟 ≈ 900 字 ≈ 50 句

`check_output.py` 会按 `--chars-per-sec` 估算总时长。**篇幅先定，再写**：
先根据发布平台定目标秒数，反推字数和句数，而不是写完再看多长。

### ⚠️ 估算值只是排期用，真实语速要实测

**实测数据（2026-09-15，535 字口播稿）**：

| 合成方式 | 语速 | 实际时长 |
|---|---|---|
| 讯飞长文本 TTS `x4_mingge` · `--speed 50`（默认） | **4.30 字/秒** | 124.5s |
| 按 5.0 字/秒估算 | 5.00 字/秒 | ~~107.0s~~ |

**默认 `--speed 50` 比 5 字/秒慢约 16%**。所以：

- 排期可以按 5 字/秒估，但**别拿它当交付时长**
- 要卡目标时长，调 `--speed`（0–100）：想从 4.30 提到 5.0 字/秒，
  按比例上调到 **`--speed 58` 左右**（讯飞语速档不是严格线性，实测校准）
- 一旦定了发音人和 speed，用 `check_output.py --chars-per-sec <实测值>` 复核，
  再 `make_tts_text.py` 重新生成 `tts.txt`

### 互动句要单独占预算，别从干货里挤

点赞引导、第一人称背书这些**不是可有可无的尾巴**，是稿子的组成部分（§8）。
排期时先把它们算进去：

| 项 | 预算 |
|---|---|
| 价值兑现 `like` 段 | 每条 1–2 句 ≈ 30–45 字；一集 1–3 条 |
| 第一人称背书句 | 1–2 处 ≈ 40–60 字 |
| 观点收束 `outro` | 1–3 句 ≈ 40–70 字 |

一条 2 分钟的稿子：干货约 **500 字** + 互动约 **100 字** ≈ 600 字。
**反过来做会翻车**：先按 600 字写完干货，再往里塞互动句，
结果就是砍数据、砍步骤，最后"干货密度"被自己稀释掉了。

另外：TTS 的**句间气口很窄**（实测平均 0.10s、最小 0.04s），
而 talkcraft 建议 ~0.3s——影响音效 cue 的落位空间。
讯飞长文本 TTS 不支持 SSML/`<break>`，只能靠标点控制停顿。

## 4. 信息取舍（最关键的一步）

一篇攻略常有 6–8 个大节、几十个信息点，**口播稿装不下全部，也不该装**。

取舍顺序：
1. **必留**：门槛条件（等级/成本）、核心操作路径、最容易翻车的坑
2. **必留**：能换算成收益的数字（尤其"白拿""省下"类的）
3. **可留**：反常识的技巧（"找人结婚升级更快"这种，最出传播）
4. **砍掉**：需要边看边查的对照表内容（动物种类大全这种）→ 改成"我放在评论区/图上"
5. **砍掉**：攻略里"具体数值见游戏内提示"这类空话

**一集只讲一件事。** 内容超了就拆上下集——这正是原攻略标题里「（上）」的意思。

## 5. 事实红线

- 攻略里的**等级、成本、坐标、NPC 名字、道具名**——原样保留，不许"润色"
- 攻略文字与攻略截图**冲突时以截图为准**（截图是游戏内实际画面），
  并在 `口播文稿.md` 的「事实核对」里标出来，让人工确认
- 攻略没写的**不要补**。没把握就用"大概""通常"，或者干脆不说
- 攻略里"具体见游戏内提示"的，口播里不能编成确定数字
- **第一人称句子同样受红线管**（§8.2）："我养了半个月""收益涨了一成"里的
  **时长和涨幅必须是真人真验过的**。没验过就换成可核验的客观表述，
  绝不允许为了有情绪而编造个人体验——这比编攻略数字更伤账号

## 6. 交付格式

`口播文稿.md` 必须包含：

1. **标题** 与来源链接
2. **篇幅表**：目标时长 / 实际字数 / 估算秒数 / 句数
3. **正文**：按段组织，每段标注 `[role]`、句号范围、对应素材 id
4. **事实核对**：从攻略继承的关键数字清单（人工过一遍）
5. **未采用内容**：砍掉了什么、为什么（方便回头补第二集）

`tts.txt` 是喂给 TTS 的配音文本（带标点、一句一行），由
`scripts/make_tts_text.py` 从 `口播文稿.md` 生成，它会核对两版逐字一致。

`script.json` 是同一份稿子的机器可读版（零标点），喂给 `video-talkcraft`
做字级时间戳。**三个文件的文字必须逐字相同，只差标点。**

## 8. 互动与叙事规则（别只把事说完）

前五节保证**说得对**，这一节保证**有人看完**。
来源：2026-09 牧场系列复盘（禽鸟篇 / 全种类篇两条反馈）。

两条主线：

- **互动**：观众要先被"兑现"才肯点赞——伸手要赞之前，得先给到东西
- **叙事**：并列罗列的信息不是内容，是清单。要给它因果、悬念、看点

### 8.1 价值兑现钩子（点赞引导不只在结尾）

**规则：每个"硬数据交付点"之后，立刻挂一次价值兑现。**

判断标准很简单——这一段有没有给出一个**能换算成收益或省下时间**的数字。
有就挂，没有别挂（空伸手会掉粉）。

四段式，缺一段就弱：

| 段 | 干什么 | 例 |
|---|---|---|
| ① 这招是什么 | 点明刚讲完的那个冷门技巧 | 绝食养法比全程喂养日均多 2.5 |
| ② 量化好处 | 换算成观众能感知的收益 | 帮你牧场每天多赚几十积分 |
| ③ 点赞请求 | 明确"点赞 = 对干货的认可" | 觉得有用的兄弟点个赞 |
| ④ 下集钩子 | 给继续关注的理由 | 后面还会挖更多省时间的赚钱小妙招 |

| 版本 | 文案（拆成 3 句，每句 ≤42 字） |
|---|---|
| 人读版 | ① 绝食养法比全程喂养日均多 2.5。② 这个冷门技巧帮你牧场每天多赚几十积分。③ 觉得有用的兄弟点个赞，我后面还会挖更多省时间的赚钱小妙招。 |
| 零标点版 | 绝食养法比全程喂养日均多2.5／这个冷门技巧帮你牧场每天多赚几十积分／觉得有用的兄弟点个赞我后面还会挖更多省时间的赚钱小妙招 |

落段规则：

- `role: "like"`，**独立成段**、1–3 句，不要塞进 body 段尾
- 一集 1–3 次：≤20 句至少 1 次；长稿（≥40 句）2–3 次
- **别每段都挂**——连着要赞等于骚扰
- 禁止：空泛的「点赞关注一波」、没兑现先伸手、「不点赞就…」式要挟

### 8.2 第一人称实操背书

**规则：≥20 句的稿子，至少一处"我"字句，把攻略结论变成真人验证。**

结构：`我自己 + 时长/规模 + 真实结果 + 情绪 + 验证方式`

| 版本 | 文案（拆成 5 句） |
|---|---|
| 人读版 | ① 我自己用这个方法养了快半个月。② 真的不用天天上线喂饲料。③ 省下的时间我多刷了好几轮任务。④ 积分收益反而比之前高了一成。⑤ 我当时算完数据都惊了，核完才敢讲给你们听。 |
| 零标点版 | 我自己用这个方法养了快半个月／真的不用天天上线喂饲料／省下的时间我多刷了好几轮任务／积分收益反而比之前高了一成／我当时算完数据都惊了核完才敢讲给你们听 |

**⚠️ 红线（本节最重要的一条）**：`我` 句里出现的**任何数字，必须是真人真验过的**。
没养过半个月就别写"半个月"，没算过就别写"高了一成"。
**没有实操时的替代写法**（可核验、不虚构）：

> 照这张表养下来日均 17.8 万，比 10 天模式多 1.4 万 —— 这是表里算得出来的，不是编的。

为有情绪而编造个人体验，比编攻略数字更伤账号。

落点：这些句子在 `口播文稿.md` 的「事实核对」里**单列一张「个人背书句（非攻略事实）」表**，
标"可替换 / 需本人确认"，录制前人工过一遍。
语气：口语第一人称，用"我"，不用"笔者""大家"。

### 8.3 完整性：来龙去脉 + 观点收束

观众不该看完还不知道"这事为什么发生""你到底怎么看"。

- **intro 交代来龙去脉**（1–2 句）：前情是什么、版本有什么变化、上一集结论是什么。
  例：「现在世界上收不到窝了，只能靠繁殖、二黑子和积分买」——
  先讲清前提，后面的养法才立得住。
- **长稿（≥8 段）必须有 `outro`**，三件事：
  1. **我的判断**：这堆数据里哪个最值钱、哪条是坑
  2. **可迁移的知识**：观众能拿走的一条原则（不只是"记住这张表"）
  3. **下一步**：照着做的第一件事是什么
- 禁止用「以上就是全部内容」「大概就是这样」收尾——那是没观点。

### 8.4 因果配对（段内必须有"因为"或"所以"）

**规则：每个 body 段都要因果成对，不许只抛结论。**

- 先果后因 → 制造悬念，适合反常识结论
- 先因后果 → 讲清机制，适合操作型内容

写进段级 `logic` 字段：`"effect→cause"` 或 `"cause→effect"`。

| | 文案 |
|---|---|
| ❌ 只有结论 | 金钱龟日均最高。 |
| ✅ 先果后因 | 6 类里金钱龟日均最高，因为它的寿命最长，养法又和熊猫完全一样。 |

语言标记：所以 / 因为 / 原因是 / 结果就是 / 代价是 / 但 / 这样一来。

### 8.5 叙事主轴（长稿要在 intro 里说破）

**规则：段数 ≥8 的长稿，`meta.axis` 必须声明主轴，并在 intro 里告诉观众。**

| axis | 推进方式 | 适用 |
|---|---|---|
| `time` | 早中晚 / 第 1、2、3 天 / 春夏秋冬 | 有明确时间线的流程（3 种养殖模式按天数讲） |
| `space` | 第一个地方、第二个地方、最后一个 | 并列类目（6 类动物逐个讲） |
| `event` | 遇到问题 → 尝试了什么 → 结果 | 带转折的实操（繁殖失败怎么救） |

**主轴必须说破**：「我按天数从短到长讲」——
观众看到路线图，才愿意陪你走完。不说破的并列罗列 = 清单，看到第 3 段就划走。

### 8.6 段首悬念（每段开头藏一样）

**规则：每个 body 段的**第一句**藏住 时间 / 地点 / 人物 / 事件 中的一项，
或抛一个反常识的半截结论；第二、三句之内必须兑现。**

写进段级 `suspense` 字段（一句话写清藏了哪一项），分镜据此设计悬念镜。

| 藏哪项 | 段首写法 | 同段兑现 |
|---|---|---|
| 事件 | 孔雀有个卖出标志，九成人看错了 | 不是老年前一天，是饱食度 74 |
| 时间 | 第 7 天有个动作，做了收益翻一倍 | 第 7 天收完直接卖掉 |
| 人物 | 有一种动物一口饲料都不用喂 | 孔雀，每 2 天只掉 4 点饲料 |

**留而不还 = 骗观众**。悬念必须在本段内兑现，不许跨段吊着。

### 8.7 看点密度（每段一个"值得看"的点）

**规则：每个 body / tip 段标 `highlight`：**

| 值 | 看点 |
|---|---|
| `reversal` | 转折（以为 A 结果是 B） |
| `surprise` | 突发意外（繁殖失败、断窝） |
| `funny` | 搞笑镜头（不停点放出收回刷寿命） |
| `payoff` | 高光 / 精彩（数字落地的那一刻） |
| `data` | 数据冲击（日均对比、反超） |

分布三条：

1. **相邻两段不重复同一类型**（连着三段 `data` = 没有起伏）
2. 一集至少覆盖 **3 种**类型
3. `data` 不超过 body 段的一半——全是数据冲击，等于全都不是冲击

看点要落到画面：这段素材的 `what` 里写清镜头怎么表现它（见 `asset-mapping-spec.md` §6）。

### 8.8 热点元素（BGM / 特效 / 表情动作）

**规则：段级 `meme` 字段标注这处可以上当期热点，一集 2–4 处，
集中在悬念兑现处和 `highlight` 处。**

**⚠️ 不写死热点名。** 写「当期热梗 BGM」「反转音效」「震惊表情包」——
规范里写死的梗，三个月就馊了，制作时按上线日期替换。

### 段级字段汇总

| 字段 | 值 | 谁在用 |
